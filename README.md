# MsgHub 留言汇

网站留言统一管理平台：多个网站的访客可以在网页上和客服实时对话，也可以提交留言；所有对话和留言汇总到一个后台集中处理。

已实现网页实时对话、QQ 官方机器人双向回复、图片与 AI 接待；正在按开发路线完善网页体验和客服效率工具。

## 功能

- **网页实时对话**：网站嵌入一行代码即出现咨询按钮，访客无需登录即可和客服实时聊天；刷新、换页后记录保留，客服回复时按钮显示未读数
- **对话后台**：会话列表实时更新（未读数、访客是否在线），直接回复、结束 / 重新打开对话，浏览器标题与通知提醒新消息
- **快捷回复**：维护全局/站点话术，聊天时插入到输入框，编辑后发送
- **会话内部备注**：按时间追加跟进记录，仅在客服后台显示，不发送给访客或 QQ
- **会话标签**：预设及自定义标签、按标签筛选、单条或批量添加/移除，仅客服可见
- **历史会话搜索**：按编号、称呼、联系方式或完整聊天内容查找，组合站点/标签/状态/消息日期筛选；会话分页、命中片段及原消息定位，支持继续加载前后聊天记录
- **留言与会话关联**：自动转留言可回看来源会话，会话内可查看和处理关联留言；处理状态独立保存，来源会话删除后仍保留留言
- **多站点接入**：每个网站一个独立 Site Key，可限制允许的来源域名（Origin）、单独启用/停用、重置 Key
- **四种接入方式**：嵌入式表单挂件、右下角悬浮按钮、自有 HTML 表单直接提交、后端 API 调用（后台「站点」页可一键复制接入代码）
- **留言管理**：按站点 / 状态 / 关键词筛选，状态流转（未读 → 已读 → 已处理 / 垃圾），内部备注，批量操作，导出 CSV（Excel 可直接打开）
- **防刷**：每 IP 频率限制、蜜罐字段过滤机器人、长度限制
- **Webhook 推送**：新留言实时 POST 到你指定的地址（可对接企业微信 / 钉钉 / 飞书机器人中转、自有系统等）
- **零外部依赖**：SQLite 单文件存储，前端无 CDN 依赖

## 部署（Docker）

```bash
cp .env.example .env      # 设置 ADMIN_PASSWORD
docker compose up -d --build
```

打开 http://127.0.0.1:20100 ，用 `ADMIN_PASSWORD` 登录。

> 网站访客的浏览器需要能访问 MsgHub，公网使用请放在 Nginx / Caddy 等 HTTPS 反向代理之后，
> 并把 `.env` 中 `BIND_ADDR` 保持为 `127.0.0.1`。服务信任 `X-Forwarded-For` 来获取访客真实 IP，
> 若直接暴露端口到公网，访客可伪造该请求头绕过 IP 频率限制。

### 反向代理需要支持 WebSocket

在线对话走 WebSocket（`/api/chat/ws`、`/api/admin/ws`）。Caddy 默认支持；Nginx 需要：

```nginx
location / {
    proxy_pass http://127.0.0.1:20100;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_read_timeout 300s;
}
```

服务必须**单进程**运行（不要加 `--workers`）：在线连接保存在进程内存里。

数据全部在 `./data`（`msghub.db` + `.secret`），备份这个目录即可。

## 对接 QQ 官方机器人

客服只需一个 QQ：访客消息转发到 QQ，客服在 QQ 里回复，访客网页上实时看到。

1. `.env` 填写 `QQ_APP_ID`、`QQ_APP_SECRET`（q.qq.com 机器人的开发设置），`docker compose up -d` 重启
2. 后台「站点」页顶部的 QQ 卡片显示“凭据有效”后，复制其中的**回调地址**（`https://你的域名/api/qq/callback`），
   填到 q.qq.com 的回调配置，订阅单聊消息事件。回调地址必须是 HTTPS，端口限 80 / 443 / 8080 / 8443
3. 点「生成绑定码」，用客服的 QQ 给机器人发送 `/绑定 123456`，收到“绑定成功”即完成

客服在 QQ 里的用法（给机器人发 `/帮助` 可随时查看）：

| 操作 | 效果 |
|---|---|
| 引用某条转发消息后回复 | 发给那位访客 |
| `#12 内容` | 发给 12 号会话 |
| 直接发文字 | 发给当前会话（最近转发过来的那个），机器人回执“已发给 #12” |
| `/列表` `/历史 #12` `/总结 #12` `/切换 #12` `/结束 #12` `/忙` `/在` | 管理会话与查看 AI 总结 |

转发策略：先发主动消息；明确失败时若客服 5 分钟内发过消息则改用被动回复；都失败则积压，客服下次给机器人发任何消息（如 `/在`）时尝试补发，后台每 30 秒扫描到期任务，失败按 30–900 秒退避。
同一会话 2 秒内的多条消息会合并成一条。为防止回错人，新会话消息刚进来的 10 秒内，“直接发文字”不会发出，需引用或用 `#编号`。

引用找不到会话时，机器人会提示用 `#编号 内容` 指定。引用和显式编号指向不同会话时会拦截。直接回复使用回调到达时的默认会话。如果默认会话已切换，机器人会要求明确指定。

已绑定 QQ 时，访客消息和待转发状态一起保存。QQ 回调在写入本地队列后才确认接收。客服发出的文字和图片与处理完成状态一起写入会话。重启后继续处理剩余回调，重复回调不会重复写入客服回复。后台「站点 → QQ 机器人」可以查看待处理和最终失败的接收任务数量。

后台「站点 → QQ 机器人 → 查看投递记录」可按类型、状态和会话编号筛选访客转发与转人工通知，查看来源消息、分段进度、失败原因、重试次数和时间，并手动补发未完成部分（间隔至少 10 秒）。长消息与图片分别保存进度，自动/手动补发串行执行，跳过已确认成功的分段；图片格式不支持或文件缺失时改发文字提示。

发送超时、QQ 服务异常、缺失回执或发送途中重启会进入「结果未确认」，暂停自动补发。请先在 QQ 核对，再选择「已在 QQ 确认收到」或确认风险后补发未确认部分；外部发送与本地落库之间无法保证绝对不重复。更换或解除客服绑定会取消旧账号的未完成投递。成功表示 QQ 接受发送请求（或客服人工确认），不代表已读。

**转人工通知**：非工作时间、客服忙碌、超时未回复，以及 AI 判断需要人工、调用失败或返回空答案时，自动记录留言并向已绑定客服发通知。通知含具体原因、站点、访客及联系方式、来源页面/会话/留言编号和访客原话摘录（最多选取首 2 / 尾 3 条并截短）；AI 可用且生成成功时另附会话总结、客户需求与提取的联系方式。引用通知或使用 `#编号 内容` 可回复来源访客，后台可跳转到来源对话或留言。

留言、转人工通知快照与自动处理进度在同一事务保存，相同来源批次不会重复建档。通知失败可独立于访客转发自动/手动补发；某一类积压不会阻止同一会话另一类投递。会话被客服回复/结束或来源留言处理/删除后，补发检查会取消过时通知。AI 等待期间客服已接管的会话不会再新增转人工通知。未配置机器人或未绑定客服时只保存留言，不在后续绑定时补发旧通知。

投递记录保留此前版本的访客转发，本次升级起加入新转人工通知；旧访客积压在再次发送时建档。普通 AI 回答提醒和机器人指令回执暂未纳入此记录。

**AI 会话总结**：在全局和本站 AI 均开启、模型配置完整时，AI 判断转人工后自动生成总结，并在成功时附到 QQ 通知。AI 应答调用本身失败时直接转人工，不额外等待总结；快速接待最多额外等待 3 秒附上总结，超时就用访客原话转留言及发通知。手动总结调用最多等待 20 秒。此功能不批量回填旧会话，也不在每条消息后调用模型。

客服在 QQ 发送 `/总结 #12`（省略编号使用当前会话），或后台对话信息栏点击「AI 会话总结 → 生成 / 更新总结」，可手动生成最新总结，包括已结束会话。相同消息范围复用成功快照；失败可重试，有新增消息时更新并保留旧快照。后台可切换最近 20 个快照，QQ 投递详情可打开通知当时使用的成功总结；生成期间有新消息时提示内容已过期。

总结仅使用当前会话最近最多 60 条访客/客服/AI 消息，总文字最多 12000 字，截短时明确提示；图片仅以未识别标记表示。内部备注、标签、知识库及自定义应答提示不进入总结输入。需求与联系方式只接受带有效访客文字消息编号、连续原话的提取项，联系方式还必须原样出现在原话中；无法匹配的项丢弃。总结与需求仍是模型生成内容，原话匹配不保证语义或联系方式归属正确，需客服核对；不自动修改访客姓名或联系方式。

总结与原始聊天快照仅管理员和已绑定 QQ 客服可见，不发给访客、不进入 AI 接待历史。自动总结与转留言/通知/处理进度同事务保存；通知补发沿用原快照，不重新调用模型。错误记录只保存通用错误分类，不保存模型服务原始错误、密钥、接口地址或系统提示。删除会话/站点按外键清理。

**AI 分类、标签与优先级**：后台「AI」增加「自动分类与 QQ 高优先级提醒」和「自动添加有原话依据的现有标签」两个独立开关，默认关闭。自动运行同时要求全局和本站 AI 开启、模型已配置；只为开启后收到的新访客消息建任务，不批量处理历史会话。已入队任务重启后继续，关闭自动分类时暂停；再次开启会继续未完成任务。分类独立于 AI 自动应答和会话总结，最多额外调用一次模型/每会话每 30 秒，最多同时处理两个会话；连发消息先合并，模型最多等待 20 秒，失败间隔至少 60 秒重试、同一批最多尝试 3 次，之后新消息或人工请求可再试。

类别固定为售前咨询、技术支持、售后服务、投诉、退款、其他；分类、优先级和标签建议必须附访客文字原话与消息编号，高优先级的依据还必须晚于客服最后回复。无效依据丢弃，语义判断仍由模型完成，需客服核对。输入仅取本会话截至最新访客消息的最近最多 60 条公开聊天、最多 12000 字，以及前 100 个现有标签的编号和名称；不传内部备注、其他会话、知识库、密钥和额外应答提示。图片不识别内容，长记录标明截短。

开启自动加标签后只追加目录中仍存在且未改名的标签，每次最多 5 个，保留已有标签；客服通过单条或批量操作移除的标签会禁止在该会话自动加回。主动再次添加，或明确点击「应用仍有效的标签建议」/QQ `/加标签 #编号`，可恢复这个标签；旧建议中的已改名/已删除标签会跳过，有新访客消息的旧分析不能应用。

QQ `/分类 #编号` 可手动分析，后台会话「分类 / 优先级」可查看最近 20 个快照、原话依据和聊天快照，并更新分析/应用建议。手动分析不会自动添加标签或发送 QQ 提醒。会话列表显示 AI 类别和高优先级待处理标记，支持分类、优先级与现有搜索/站点/日期/标签组合筛选。客服回复或结束会话后不再标为待处理；QQ `/普通 #编号` 或后台「取消高优先级」可撤销当前及在途分析对已有访客消息的提醒，之后有新访客原话才可能重新建议高优先级。

自动分析在有新消息、已接管/结束、关闭开关或更换绑定时不发过时提醒。高优先级通知写入持久化 QQ 投递记录，与分类/自动标签同事务提交；同一待回复轮次每 30 分钟最多建一条提醒，相同批次去重，失败/未确认沿用分段检查点和受控重试。提醒、转人工、普通访客转发各自保序互不阻塞。投递详情可打开对应分类依据；未绑定不创建旧提醒，更换绑定会清理旧分类任务。撤销/回复/结束后未发送的提醒停止补发，已被 QQ 接受或正在传输的消息无法撤回。

所有分类记录、标记、任务与标签屏蔽仅对管理员开放，不发给访客或写入接待 AI 历史，不改变聊天内容/未读/会话状态；错误只保存通用分类。删除会话/站点级联清理，标签删除清理屏蔽关系但保留原分析快照。接口读取与生成均需登录。

## 站点设置与 AI 自动应答

每个站点（后台「站点」→ 编辑）可设置：欢迎语、对话前必须留称呼和联系方式（默认开启）、工作时间、非工作时间提示语。

**AI 快速接待**：全局与站点均启用 AI 且模型配置齐全时，访客发来消息后约 2 秒开始处理，连发内容合并一批，工作时间内外都一样。挂件会显示 AI 正在处理。AI 根据问答库和网页资料回答，回答同步给 QQ。需要人工、模型失败或等待超过 12 秒时，系统转留言并向已绑定 QQ 发提醒。存在模型转人工摘要时，最多再等 3 秒补充到通知。

**人工接待**：客服回复后，本轮由人工接待。AI 已经转人工的会话，访客追加消息会补到留言和 QQ 接待流程。结束会话后访客再次发消息，开启新一轮接待。未配置 AI 的站点在非工作时间或客服忙碌时转留言。在工作时间内，留给人工的未回复时限由设置决定，默认 3 分钟。

**AI 配置**（后台「AI」页）：兼容 OpenAI 的接口地址（填到 `/v1`）、API Key、模型名。
资料来源：问答库（优先）+ 网站内容（每天自动抓取站点域名或指定起始地址，同域名最多 50 页，遵守 robots.txt）。
页面上可以直接输入问题测试 AI 的回答、转人工分类和结构化参考资料；测试使用同一套检索和分类逻辑，不创建真实会话记录。

**参考资料与处理依据**：后台对话信息栏点击「AI / 转人工依据」，或在 AI 消息下点击「参考资料与处理依据」，可分页查看处理记录。QQ 转人工投递详情也能直接打开对应依据。记录保存处理时的问题/回答、模型、触发条件、处理分类，以及本次实际提供给模型的问答/网页片段、标题、站点范围和网址；原资料后来修改或删除，快照仍保留。

参考资料表示模型当时收到的内容，不代表回答逐句引用或事实已核验。资料不足、访客要求人工、需人工办理等分类由模型返回，页面明确标注；服务异常、空回答、未启用或配置未完成属于系统状态。普通旧 `[转人工]` 标记继续兼容，显示未提供具体分类。资料按相关度排序，最多 8 段、合计 3500 字，超长片段截取并标明；不会混入其他站点资料、内部备注或标签。

处理记录、AI 消息、转留言/QQ 通知和自动处理进度在同一事务保存，失败一起回滚。记录仅管理员可见，不进入访客 WebSocket 历史或 AI 对话历史，不保存 API Key、接口地址、系统提示或服务商原始错误。该功能从本次升级开始记录，旧消息不补建；问题快照最多保存 6000 字并提示截短，删除会话/站点时级联清理。

**图片**：访客可点按钮或粘贴发送图片（PNG/JPG/GIF/WebP，≤5MB），客服可在网页后台或 QQ 里发图片。
QQ 只支持 PNG/JPG，其他格式会提示客服到网页后台查看。图片保存在 `./data/uploads`。

## 接入示例

```html
<!-- 在线对话：右下角咨询按钮 -->
<script src="https://msg.example.com/embed.js" data-site-key="sk_xxx"></script>
```

| 属性 | 说明 |
|---|---|
| `data-site-key` | 站点 Key，必填 |
| `data-target` | 嵌入到页面中的某个容器（如 `#msghub`），不填则为右下角悬浮按钮 |
| `data-mode` | `chat`（默认，在线对话）或 `form`（旧版留言表单） |
| `data-title` / `data-color` / `data-welcome` | 标题 / 主题色 / 欢迎语 |

```bash
# 后端直接调用
curl -X POST https://msg.example.com/api/public/messages \
  -H "Content-Type: application/json" -H "X-Site-Key: sk_xxx" \
  -d '{"name":"张三","contact":"13800000000","content":"想咨询一下价格"}'
```

### 提交字段

| 字段 | 说明 |
|---|---|
| `site_key` | 站点 Key（也可用请求头 `X-Site-Key`） |
| `content` | 留言内容，必填，≤ 5000 字 |
| `name` | 称呼 |
| `contact` | 联系方式 |
| `page_url` | 来源页面，缺省取 Referer |
| `_redirect` | 表单提交成功后跳转的地址（仅 HTML 表单需要） |
| `_hp` | 蜜罐字段，隐藏且留空；有值视为机器人 |

### Webhook 数据格式

```json
{"event":"message.created","site":"官网","id":1,"site_id":1,"name":"张三",
 "contact":"138...","content":"...","page_url":"...","ip":"...","user_agent":"..."}
```

## 目录结构

```
msghub/
├── app/
│   ├── main.py        # 路由：公开提交接口 + 管理接口
│   ├── chat.py        # 在线对话：访客 / 后台 WebSocket、对话接口
│   ├── qq.py          # QQ 官方机器人：回调验签、转发、客服指令
│   ├── qq_delivery.py # 访客转发队列、分段进度、记录与受控补发
│   ├── auto.py        # AI 自动应答、转留言、网站内容抓取
│   ├── summaries.py   # 私有会话总结、需求与联系方式提取
│   ├── triage.py      # 私有会话分类、标签建议、优先级与持久化任务
│   ├── media.py       # 图片上传与存储
│   ├── common.py      # 限流、来源校验
│   ├── db.py          # SQLite 表结构
│   ├── auth.py        # 管理员登录令牌
│   ├── config.py      # 配置
│   └── static/        # 管理后台（index.html/admin.js/admin.css）与 embed.js 挂件
├── data/              # 运行数据（已 gitignore）
├── Dockerfile
├── docker-compose.yml
└── .env.example
```
