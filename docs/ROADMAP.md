# MsgHub 开发路线

## 目标

把 MsgHub 做成客服每天可以稳定使用的轻量工作台：新消息一眼可见，回复、查资料和处理留言都在一个连续流程里完成；访客挂件在桌面和手机上都保持清晰、可信和易用。

客服接待端只使用 QQ；网页后台用于站点、知识库、记录和运行状态管理。后续通知与接待能力围绕 QQ 完善，不扩展企业微信、飞书、邮件或 Telegram 客服渠道。

## 当前基线

当前版本已上线，用户已确认实际 QQ 接待可用。后续进入日常维护，新增功能按使用中遇到的问题安排。

- [x] 网站留言、限流、蜜罐和 Webhook
- [x] 访客与后台 WebSocket 实时对话
- [x] 图片消息和本地上传
- [x] QQ 机器人转发、引用回复和客服指令
- [x] 工作时间、离线留言和 AI 自动应答
- [x] 问答库、网站抓取和 AI 测试
- [x] Docker Compose 与 Caddy 反向代理部署

- [ ] 多客服协作

## 阶段 1：网页端视觉重构

目标：不改变后端接口，先让后台和访客挂件具备稳定的视觉层级、响应式布局和完整状态反馈。

- [x] 建立颜色、间距、边框、按钮和表单控件的统一设计变量
- [x] 重做后台顶部导航、统计区、会话列表和聊天工作区基础层级
- [x] 优化留言、站点、AI 页面的信息密度和基础空状态
- [x] 补齐加载中、断线、空数据、错误和移动端状态
- [x] 优化访客挂件的头部、消息气泡、资料表单和图片消息
- [ ] 在桌面和手机尺寸下完成手工验收

当前进度：后台和访客挂件的第一轮视觉改造已部署。新增加载、失败重试和断线恢复后，继续保留手机真机、软键盘和其他桌面尺寸的手工验收。

- 后台各区域独立加载。统计、站点、留言、会话、快捷回复、AI 设置、问答、网站资料及 QQ 投递等读取失败时显示原因和重试入口。过期登录返回登录界面并说明原因。
- 后台识别断网和失去心跳的连接，支持自动或手动重连。重新连接后补齐当前会话消息，保留历史查看位置和回复、备注草稿。
- 访客挂件在连接及保存资料时显示状态。连接中断时保留输入，已发送但未确认的文字可以取回核对。图片上传和留言提交失败时显示原因。
- 窄屏留言列表按条显示，保留筛选、批量处理和详情。会话与挂件的输入控件根据可见窗口高度调整，打开时避免直接唤起软键盘。

网页体验发布记录（2026-11-17）：镜像 `09bd7b1fa0a1` 已部署，HTTPS 健康接口和静态资源版本已核对。隔离环境通过 49 项后端测试和 10 套 Chromium 浏览器验收。网页状态脚本也在 Firefox 和 WebKit 通过，覆盖 320/390 像素布局和模拟键盘窗口缩小。上线前的数据库备份位于 `data/backups/msghub-before-web-states-20261118-085045.db`（容器使用 Asia/Shanghai 时间），完整性检查通过。

验收标准：客服打开后台后可以快速找到待回复会话；会话列表、聊天内容和操作区在窄屏下不会互相遮挡；访客挂件不影响宿主网站布局。

## 阶段 2：客服效率工具（已完成）

- [x] 快捷回复：站点级和全局模板，输入框快速插入
- [x] 会话标签：预设标签、筛选、批量修改
- [x] 会话内部备注：仅客服可见，支持追加记录
- [x] 更完整的会话搜索：编号、访客、联系方式、内容、时间范围
- [x] 留言与会话之间的关联展示

验收标准：常见问题可以在几秒内完成回复；客服能按标签和关键词找回历史客户；内部信息不会发送给访客。

本批交付：

- 新增「快捷回复」管理页，支持新增、编辑、删除，以及全局/站点范围筛选。
- 聊天输入框仅显示该站点可用的模板，插入到光标处，由客服编辑确认后发送。
- 会话增加内部备注折叠区，追加保存并显示最近 100 条记录，不写入聊天消息、不推送访客和 QQ，也不进入 AI 对话历史。
- 修复回复/图片请求在切换会话后返回时串入其他会话的显示问题，并防止文本回复重复提交。
- 新表通过启动初始化自动创建，不修改既有消息记录；删除站点/会话时按外键规则级联清理。
- 已通过 3 组隔离数据库接口回归，以及 Chromium 模板管理、插入、备注持久化/隐私/转义、延迟响应和窄屏布局验收。

会话标签交付：

- 首次升级预设「待报价、售后、投诉、重点客户、已转化」，支持新增、重命名和删除，所有站点共用；删除或修改预设后重启不会恢复旧名称。
- 对话列表支持标签、状态、关键词组合筛选；聊天上方可添加/移除标签，勾选列表可对当前加载的会话批量操作（最多 100 条）。
- 批量操作先验证所有会话及标签，失效请求整批不修改；移除一个标签时保留其他标签，删除标签时保留聊天记录。
- 标签仅对已登录的客服开放，通过后台实时通道同步；访客在线和重连时都不会收到标签，修改标签不触发 QQ/AI、不改变会话未读和状态。
- 多个后台窗口及断线重连后刷新标签；重命名、删除和筛选期间保留当前回复/备注草稿。手机端长标签可横向滚动。
- 已通过 6 组隔离接口回归和两套 Chromium 验收，覆盖批量修改、组合筛选、双窗口同步、重连恢复、隐私、草稿保留及 1440/390/320 像素布局。

历史会话搜索交付：

- 关键词覆盖编号、访客称呼、联系方式及全部文字聊天记录，支持中文和 ASCII 大小写匹配；`%`、`_`、反斜杠按普通文字搜索，不检索内部备注或图片文件名。
- 站点、标签、状态、开始/结束日期可组合筛选。日期包含起止整天，按服务器时间和消息发生时间判断；关键词命中的消息须位于指定日期内，姓名/联系方式/编号命中的会话须在该日期内有消息。
- 会话每页 30 条，显示总数和页码；筛选变化回到第一页并清空勾选，实时更新保持当前页，末页数据减少后自动回退。
- 结果显示最近一条命中消息的片段，点击进入原消息并显示周围上下文。可继续加载更早、后续消息，或回到最新；支持定位早于最近 500 条的消息。
- 查看历史期间不把新消息拼入有缺口的上下文，回到最新后恢复实时显示。翻阅历史保留回复与备注草稿，并防止迟到的搜索/历史响应覆盖新的筛选或其他会话。
- 新增消息日期联合索引，由启动初始化幂等创建；搜索与历史读取仅对客服开放，不向访客、QQ 或 AI 推送。打开会话保持原来的标记已读行为。
- 已通过全部 8 组隔离接口回归和三套 Chromium 验收，覆盖 35 个会话分页、600 条以上聊天历史、完整搜索/时间边界、定位与草稿保留、迟到响应/新消息并发、现有模板/标签/备注功能，以及 1440/390/320 像素布局。

留言与会话关联交付：

- 留言列表展示来源会话编号，详情可直接打开来源会话；普通表单提交保留为独立留言。来源引用必须属于同一站点，防止旧数据的错误引用串到其他站点。
- 会话信息栏增加「关联留言」数量与入口，侧栏每页 10 条，可查看详情、保存处理备注、标为已处理/垃圾或删除；支持打开留言列表当前页之外的记录。
- 自动转留言继续使用既有来源字段，同一会话 24 小时内未处理的留言追加合并。创建、追加、处理和删除通过仅客服可见的事件同步留言列表与关联数量。
- 留言处理状态与会话状态分别保存；删除来源会话后保留留言内容、处理备注及原始来源编号，并显示来源不可用。删除站点仍按原有规则清理其数据。
- 关联侧栏的查看和翻页不改变聊天未读；打开留言详情时仅将仍处于未读状态的记录标为已读，不覆盖他人已处理的状态。留言详情读取和关联接口均需管理员登录，公开提交不能指定关联会话。
- 在同一会话的关联留言与聊天之间返回时保留回复、会话备注草稿；留言备注草稿在当前页面内暂存，刷新或退出后清空。关闭详情或切换记录后，迟到响应不会重新打开旧详情。
- 新增来源会话联合索引，在旧库字段迁移后幂等创建，不修改既有留言或会话内容。
- 已通过全部 10 组隔离接口回归和四套 Chromium 验收，覆盖实际离线转留言及追加、关联分页、双向跳转、状态独立、访客隐私、双窗口同步、草稿/迟到响应，以及 1440/390/320 像素布局。

## 阶段 3：QQ 接待可靠性与 AI 辅助（进行中）

- [x] QQ 投递记录：按访客消息批次展示发送结果、来源消息、分段进度、最近失败原因、重试次数与时间，并提供受控的手动重试
- [x] QQ 转发可靠性：检查并发补发、长消息分段和图片失败场景，完善防重复及异常恢复
- [x] QQ 转人工通知：补充转人工原因、访客需求摘录和来源会话，验证通知失败后的补发
- [x] AI 回复参考资料快照和转人工分类展示（供客服复核）
- [x] AI 自动总结会话、提取客户需求和联系方式
- [x] AI 自动分类、打标签和高优先级提醒
- [ ] Markdown / TXT / PDF 知识库导入（暂缓：当前尚未整理知识库，待资料准备好后再安排）

本批交付：

- 新增持久化投递批次、来源消息关联和分段快照；后台「站点 → QQ 机器人 → 查看投递记录」支持状态/会话筛选、分页、来源和分段详情、失败诊断及手动补发。
- 自动积压扫描、访客合并发送和手动补发共用串行队列；每段成功后落库，重试跳过已发送内容。同一会话优先处理旧积压，一个会话明确失败不阻塞其他会话；失败按 30–900 秒退避，手动补发至少间隔 10 秒。
- 超时、QQ 服务异常、缺少消息编号和发送途中重启标为「结果未确认」，暂停自动重发；客服核对后可以人工确认收到，或明确确认重复风险后补发未确认部分。外部发送与本地落库无法形成原子事务，不承诺绝对不重复。
- 图片失败独立于文字进度；不支持格式或图片缺失时记录跳过原因并补发文字提示。保留 QQ 消息编号与引用回复定位。
- 更换/解除绑定取消旧账号未完成投递，不把积压交给新账号；同一绑定码并发使用时只消费一次，绑定变更重置默认会话。
- 每段成功后更新带保护期的默认会话，结果不确定时清除默认目标；客服回调补发积压后重新读取目标，避免使用补发前的旧会话。
- 管理接口均需登录，不返回原始收件人标识；错误信息隐藏机器人密钥、令牌和绑定账号。投递变更事件仅发送后台，前端防止重复提交和关闭后迟到响应覆盖。
- 首批记录范围为访客转发，旧积压补发时建档；本次已扩展至下文的转人工通知。普通 AI 回答提醒和指令回执仍待补充。成功代表 QQ 接受请求或客服人工确认，不代表已读。

转人工通知交付：

- 覆盖非工作时间/客服忙碌、超时未回复、AI 判断转人工、AI 服务异常与空回答；通知包含原因、站点、访客/联系方式、来源页面、会话与留言编号。AI 转人工前已有回答时附上该回答摘录。
- 需求内容采用首 2 / 尾 3 条访客原话摘录与图片标记，限制长度并标出省略，明确非 AI 总结；不包含内部备注或标签。客服可引用 QQ 通知或用 `#编号 内容` 回复。
- 留言创建/追加、通知快照和处理进度在同一 SQLite 事务提交，按会话及来源批次去重；AI 等待期间客服回复或会话结束则不再生成过时通知。
- 转人工通知复用持久化队列、分段检查点、退避、人工确认与手动补发；积压扫描覆盖不带 pending 访客消息的独立通知。访客转发与通知各自保序，互不因对方失败/未确认而停止；同一批内容重试保持快照不变。
- 补发前检查接管/结束、留言已处理/垃圾/删除，自动取消已无须处理的通知；更换/解除 QQ 绑定沿用旧账号积压取消规则。未配置或未绑定时仅保存留言，不把历史通知补给新绑定客服。
- 记录页新增投递类型筛选、转人工原因与需求摘录、来源对话/留言跳转及来源删除状态；QQ 状态卡分别显示访客积压和待完成通知。新增字段幂等迁移，历史记录保留为访客转发。
- 详情最多显示最近 100 条来源消息并提示前往对话查看完整历史，避免大量积压使侧栏一次加载过多内容；通知本身始终保留简短摘录。
- 普通 AI 回答提醒和机器人指令回执仍沿用现有发送方式，尚未纳入投递记录；AI 自动摘要及资料来源展示已由后续批次完成。

AI 参考资料与处理依据交付：

- 检索返回结构化资料与实际传给模型的文本，保留问答编号/全局或本站范围、网页标题/URL/抓取时间/片段位置和截取标记；只选择全局与当前站点资料，不读取内部备注或标签。最多 8 段、3500 字，长问答按剩余预算截取，避免整段过长导致后续资料全空。
- 新增管理员专用处理记录，保存问题、回答、模型、触发条件、处理分类及资料快照；问题超过 6000 字时截短并标记。与 AI 消息、留言、QQ 通知及处理进度同事务提交，异常回滚；相同来源批次去重。
- 模型可返回资料不足/访客要求/需人工办理三类转人工标记，兼容旧标记及未知分类；标记不会显示给访客。模型分类明确标注来源，系统异常/空回答/未启用/配置不全分别记录，不根据是否检索到资料推断模型的具体转人工理由。
- 参考资料是当时提供给模型的内容，不能视为已验证的逐句引用或事实依据；不保存系统提示、API Key、接口地址或服务商原始错误。资料修改/删除不影响已保存快照。
