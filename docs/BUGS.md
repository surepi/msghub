# MsgHub 缺陷记录

## 2026-11-17 安全审计

P0 需要优先止血，P1 需要优先修复，P2 包含后续加固。审计发现保留在各条目，修复进度见下方。

审计范围包括当时的工作区、`msg.xincode.com` 的运行镜像、Nginx 和 MariaDB 应用账号。审计时的镜像与当时工作区的 Python 源码、前端脚本和 MySQL schema 一致。线上 QQ 已启用并绑定客服，AI 已配置，三个启用站点均配置了允许来源，均未配置 Webhook。公网 HTTPS 健康检查返回 `200`，匿名访问后台统计返回 `401`。

审计时，现有 56 项回归在临时 SQLite 环境中全部通过，QQ 和模型服务使用模拟实现。以下安全缺陷依据源码、依赖公告和只读部署检查确认，线上仅发起常规只读请求。

## 修复进度

- BUG-001 至 BUG-010 的代码和部署配置已更新，2026-11-18 已切换生产。新版关闭旧 QQ 回调，启用带独立凭据的新回调，并检查事件时间。已收到平台的地址校验请求，真实单聊收发待确认。
- 本地通过 59 项回归。独立 MariaDB 验证了旧库迁移、重复执行、访客续接、附件写入及最小权限账号。Chromium 验证了访客上传、访客和客服两侧图片加载、后台登出撤销。验收镜像以非 root 用户和只读根文件系统启动成功，29 个已安装 Python 包的 OSV 查询未命中公告。
- 生产已验证公网 HTTPS 和访客 WSS、后台鉴权、挂件资源版本，以及旧附件路径返回 404。Nginx 已关闭该站点的共享代理缓存，公网请求直达本机。MariaDB 运行账号的直接授权只有 MsgHub 库的读写权限。服务器全局 `PUBLIC` 角色仍对 `test` 和 `test_*` 保留默认授权，当前没有匹配的库。操作顺序见 [安全部署与升级](SECURITY-DEPLOYMENT.md)。

## 缺陷明细

### BUG-001 · P0 · QQ 公开回调的签名边界失效

- **影响** · 地址校验分支对未认证请求提供签名，且与正式 QQ 事件使用同一密钥。正式事件存在伪造风险。事件中的身份若匹配已绑定客服，可影响客服回复和会话操作。事件接收有持久化去重，签名校验缺少时间有效期检查。[回调路由](../app/qq.py#L683) · [签名与验签](../app/qq.py#L77) · [事件去重](../app/qq_inbound.py#L15)
- **修复** · 先按 QQ 官方支持的方式收紧回调入口，把地址校验限定在受控流程内。若无法及时限制入口，可暂时停用 QQ 回调并保留网页客服。正式事件增加与 QQ 投递重试兼容的时间窗口，保留事件去重。
- **验收** · QQ 平台能完成地址校验，正常消息可入队和回复。非受信的校验请求、无效签名和过期事件被拒绝，正常重投只处理一次。

### BUG-002 · P1 · 公开表单与文件响应依赖存在拒绝服务漏洞

- **影响** · 线上 `Starlette 0.41.3` 和 `python-multipart 0.0.20` 命中已知公告。公开表单、图片上传和文件响应使用受影响的解析或响应路径。Nginx 在审计时的全局请求体上限为 50 MB，应用的 5 MB 图片限制在 multipart 解析后执行。[依赖配置](../requirements.txt) · [留言表单](../app/main.py#L147) · [访客上传](../app/media.py#L153) · [Starlette 文件响应公告](https://osv.dev/vulnerability/GHSA-7f5h-v6xp-fcq8) · [Starlette 表单公告](https://osv.dev/vulnerability/GHSA-82w8-qh3p-5jfq) · [multipart 公告](https://osv.dev/vulnerability/GHSA-pp6c-gr5w-3c5g)
- **修复** · 联动升级 FastAPI、Starlette 和 multipart，在反代按接口限制请求体和并发，给图片上传预留表单开销。重建镜像时复核并更新命中公告的 `cryptography`、`pip` 和 `setuptools`。
- **验收** · 扫描新镜像的实际安装版本，确认适用公告已修复。正常留言和限额内图片上传可用，超限请求在业务解析前被拒绝。

### BUG-003 · P1 · 代理头可能让 IP 限流失效

- **影响** · 线上 Nginx 使用 `$proxy_add_x_forwarded_for`，Uvicorn 配置为信任所有代理并采用转发链首地址。上游若未清洗该头，留言、访客建档、发消息和上传的 IP 限流可以被绕过。限流器还只在同一键重新访问时清除旧时间戳，高基数流量下旧键会持续占用内存。[Uvicorn 启动参数](../Dockerfile#L14) · [限流器](../app/common.py#L53) · [访客消息限流](../app/chat.py#L452)
- **修复** · 在可信入口重建客户端地址头，明确 Uvicorn 信任的代理。对 HTTP 和 WebSocket 建立入口限额，定期回收过期限流键。
- **验收** · 外部提供的代理头无法改变应用记账的客户端地址。超限请求按真实客户端被限制，过期键会回收。

### BUG-004 · P1 · 访客令牌和资料没有绑定站点

- **影响** · 访客令牌在全局表中查询。持有令牌的一方可在另一个可用站点读取或覆盖该访客的姓名和联系方式，上传接口也只检查令牌是否存在。历史消息由站点和访客共同筛选。[令牌查询](../app/chat.py#L207) · [访客握手](../app/chat.py#L363) · [资料更新](../app/chat.py#L415) · [上传鉴权](../app/media.py#L165)
- **修复** · 将访客身份、令牌及资料更新绑定到站点，握手与上传统一校验。迁移已有访客数据时保留合法的同站会话续接。
- **验收** · 同站重连能恢复资料及历史。另一站点无法凭原站令牌读取、修改资料或授权上传。

### BUG-005 · P1 · 聊天附件可凭链接公开访问

- **影响** · `/uploads/` 原通过静态路由公开提供，持有链接即可读取图片。响应允许公共缓存一年。图片引用只检查文件是否存在，删除会话后磁盘上的图片仍可访问。[新版缓存控制](../app/main.py#L44) · [图片归属校验](../app/media.py#L104) · [会话删除](../app/chat.py#L951)
- **修复** · 记录附件归属，下载时校验会话权限或签发短期链接。迁移历史图片时处理旧公开路径和缓存，按留存策略清理孤立附件。
- **验收** · 合法访客和客服仍可在聊天中查看图片。越权引用、过期链接和旧公开路径均被拒绝。清理附件后，旧链接无法继续从源站或受控缓存下载。

### BUG-006 · P1 · 管理员登录限流与会话撤销缺失

- **影响** · 登录失败仅延迟一秒。令牌默认有效七天，退出只删除浏览器中的副本，修改密码不会使旧令牌失效。后台 WebSocket 只在握手时检查有效期。[登录接口](../app/main.py#L230) · [令牌配置](../app/config.py#L14) · [退出处理](../app/static/admin.js#L117) · [后台 WebSocket](../app/chat.py#L494)
- **修复** · 增加登录失败限流和可撤销的短期会话。退出、改密或过期时，REST 会话和关联 WebSocket 一并失效。
- **验收** · 连续失败触发限流，正常管理员可登录。退出、改密或到期后，旧令牌无法访问接口，已有连接停止接收事件。

### BUG-007 · P2 · 服务端出站连接缺少目的地址限制

- **影响** · 知识抓取、AI 请求、Webhook 和 QQ 图片下载跟随重定向时缺少统一的目的地址检查，可能访问容器可达的内部服务。知识抓取的链接域名检查不能约束 HTTP 跳转的目的地。[知识抓取](../app/auto.py#L643) · [AI 请求](../app/auto.py#L183) · [Webhook](../app/main.py#L129) · [QQ 图片下载](../app/qq.py#L486)
- **修复** · 按用途校验协议和目的地，在连接及每次重定向时检查实际目标。模型和 Webhook 含凭据或访客数据的请求使用受信 HTTPS，并对访客触发的 AI 调用设预算上限。
- **验收** · 合法网页、模型服务和 QQ 图片仍可访问。未获准的私网目标及跳转被拒绝，凭据不会随跳转转交给其他主机。

### BUG-008 · P2 · 留言提交允许跳转到未授权的外站

- **影响** · 公开留言接口使用请求中的 `_redirect` 作为成功返回地址。允许来源和站点 Key 的校验没有约束实际跳转目标，蜜罐分支也单独返回跳转。[成功与蜜罐跳转](../app/main.py#L187)
- **修复** · 由站点配置允许的回跳地址，所有跳转分支使用同一校验。
- **验收** · 已配置的回跳正常工作，未授权目标不会进入响应的 `Location`。

### BUG-009 · P2 · CSV 导出缺少公式中和

- **影响** · 访客可控的姓名、联系方式和留言内容原样写入 CSV。客服使用表格软件打开时，部分字段可能被识别为公式。[CSV 导出](../app/main.py#L473)
- **修复** · 保留标准 CSV 转义，并在写入用户可控字段前执行公式中和。
- **验收** · 表格软件将公式样式字段作为文本呈现。逗号、引号、换行及中文仍能正确导出和读取。

### BUG-010 · P2 · 容器和数据库账号权限过宽

- **影响** · 容器以 root 运行，根文件系统可写，无内存和进程数上限。MariaDB 应用账号对 MsgHub 库拥有全部权限，还有两项指向其他库范围的授权。审计时该账号仅能看到 MsgHub 业务库。宿主机数据库 socket 的只读挂载不会限制账号可以执行的 SQL。[镜像构建](../Dockerfile#L1) · [容器部署](../docker-compose.yml#L10) · [启动建表](../app/mysql_db.py#L96)
- **修复** · 为容器配置非 root 用户、受限文件系统和资源上限。把建表等迁移权限交给独立账号，收回运行账号的多余授权。
- **验收** · 镜像重建后可启动并访问 MariaDB，留言、聊天、附件与正常备份流程可用。运行账号无法修改 schema 或访问其他业务库。

### BUG-011 · P1 · 翻看聊天历史时新消息被提前标为已读

- **影响** · 客服停留在同一会话的历史窗口时，新消息暂不插入当前窗口，但实时事件仍会清除该会话的未读计数。客服可能漏看新消息。[历史窗口逻辑](../app/static/admin.js#L1370) · [实时事件处理](../app/static/admin.js#L1814) · [标记已读](../app/static/admin.js#L1671)
- **证据** · 已在隔离 Chromium 复现。访客发来新消息后，后台仍显示历史窗口，新消息未出现，服务端未读计数已归零。
- **修复** · 仅在客服处于当前会话的最新消息窗口且新消息已展示时自动标为已读。历史窗口中的新消息保留未读提示，回到最新消息后再更新已读状态。
- **验收** · 保持历史窗口时，连续收到新消息仍保留对应未读。切回最新消息并展示新消息后，未读计数更新。

### BUG-012 · P2 · 对话打开超过图片链接有效期后无法查看原图（暂不修复）

- **影响** · 图片签名链接有效期为 10 分钟。客服或访客长时间停留在对话页，点击原图时仍使用旧链接，过期后返回 404。客服后台延迟加载的历史图片也可能受影响。[签名链接](../app/media.py#L76) · [客服图片展示](../app/static/admin.js#L1332) · [访客图片展示](../app/static/embed.js#L274)
- **证据** · 已在隔离 Chromium 缩短签名有效期复现。过期链接返回 404，重新打开同一会话后获取的新链接可访问图片。
- **当前处理** · 客服重新打开会话，访客刷新网页，均可获取新的短期签名链接。

### BUG-013 · P1 · 停用站点或重置 Site Key 后旧访客连接未立即断开

- **影响** · 站点停用或重置 Site Key 后，已有访客 WebSocket 不会被主动关闭。心跳分支跳过站点状态检查，旧连接在发来新的业务消息前仍可能收到后续客服回复。[站点更新](../app/main.py#L340) · [重置 Site Key](../app/main.py#L353) · [访客连接](../app/chat.py#L399) · [访客推送](../app/chat.py#L73)
- **证据** · 已确认源码中的配置更新和连接处理路径。本次未在线上触发站点停用或密钥重置。
- **修复** · 站点配置变更提交后，立即使该站点的旧访客连接失效。向访客发消息前校验连接资格，防止配置变更与消息推送并发时继续向旧连接发送。
- **验收** · 停用站点或重置 Site Key 后，已有连接立即关闭，旧连接无法继续接收消息。停用站点拒绝重连，启用站点可用新 Key 正常连接，其他站点的连接仍可收发消息。
